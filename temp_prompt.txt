1. WHAT THE PRODUCT IS
====================================================================================================
A procurement-evaluation prototype for ports & customs.
- A customer creates a project (tender) with its RFP documents, applies "standards" (the
  organisation's rule sets) and adds vendors with a commercial and a technical proposal (PDF/Word…).
- Claude analyses every vendor against the standards and, separately, against the RFP; finds
  risks; recommends a vendor.
- Everything is shown with evidence that opens the vendor's document highlighted.

ANALYSIS PIPELINE (src/server/ai/*, src/server/runs/*), 3N+2 steps
- Order: checklist → standards check per vendor → RFP check per vendor → risk register per vendor
  → recommendation.
- Proposals follow a 7-section template (PROPOSAL_SECTIONS in src/lib/domain.ts): company,
  solution, security, implementation, support, commercial, terms.
- Every requirement, finding and risk has a section and a one-line headline, stored in the new table
  analysis_meta. src/lib/sections.ts guessSection() is a weighted keyword score, used by the mock
  engine and as a fallback.
- Scores are computed by the app, never by the AI (src/lib/scoring.ts, src/server/runs/scores.ts):
  - Standards % and RFP % use the settings weights and partial credit.
  - Risk score = 45×min(1, mandatory not met/5) + 30×gap share + 25×(average of the top-3 L×I/25).
    Bands: <25 low, <50 moderate, <70 high, else critical.
  - Overall = 0.4 Std + 0.4 RFP + 0.2(100−risk); without standards, 0.8 RFP + 0.2(100−risk).
  - The recommendation is the formula's pick; the AI only writes the reason.
- The system prompt forbids writing the input's "Section A–E" labels (a live run once wrote
  "Section E"; that old run's text still shows it).

AI ANALYSIS RESULTS PAGE
- URL: /analysis/[projectId]?run=&tab=overview|rfp|standards|risks|comparison|quality&reader=&page=&q=&v=
- While a run is active it shows "mission control" (live steps, ETA, phases, vendor boxes of equal
  height).
- Tabs:
  - Overview: the recommended-vendor box with the AI reason, 3 mini boxes, per-vendor rows.
  - RFP and Standards (separate tabs; there is no "Compliance" tab any more):
    - vendor-first cards in ranking order, each labelled "Vendor N of M";
    - a tinted summary band with the overall %, then "By proposal section" rows;
    - a row opens its points with status pills (non-compliant / partial / not addressed /
      compliant; one group at a time);
    - empty sections are listed once at the end.
  - Risks: vendor-first in the same way; "View more" links the clause or rule, the evidence, and
    "see its points".
  - Comparison: pick ≥2 vendors, then a pricing-page style table (one column per vendor; rows for
    overall, RFP by section, standards by section, risks by section, commercial terms; the best
    value is marked). It is computed from saved results, with no AI call. An optional AI-written
    comparison summary was offered (~$0.01–0.02 on Haiku); the user has not answered.
  - AI quality: run report + human review.
- A "Latest analysis ▾" menu holds the run history. Old /projects/:id/evaluation and /ai-review
  URLs redirect here.
